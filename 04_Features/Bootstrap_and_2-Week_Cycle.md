# Bootstrap and 2-Week Cycle

## Main principle

While performing exercises, the system must not distract the user.

The user does the session first, and feedback is collected afterward — separately for each exercise.

## First run

The goal of the first run is to quickly gather a minimal context and start the first 2-week cycle.

### 1. Greeting

Example:

> Hi. Let's set up the recovery tracker.
> You define the goal, exercises, and reference performance.
> I'll help record sessions, collect feedback, and show the trend.

### 2. About the user

At minimum:

- what we're recovering;
- date of surgery/injury;
- current recovery stage;
- current restrictions;
- what's bothering you now;
- which movements are especially important.

### 3. Goal for 2 weeks

Example goals:

- do exercises regularly;
- reduce fear of movement;
- understand pain dynamics;
- improve range of motion;
- reduce torso/scapula compensation;
- collect a clear progress summary.

### 4. Choosing exercises for 2 weeks

The user picks a small set of exercises from the database or adds them manually.

For each exercise, define:

- name;
- reference performance;
- frequency;
- sets/reps/time;
- what to track;
- exercise importance;
- restrictions;
- comments.

## Daily session

### Before the session

The user picks the workout/exercises for today.

The system shows a short plan:

- list of exercises;
- order;
- camera reminder;
- key technique points.

### During the session

The system doesn't distract.

It doesn't ask questions between reps and doesn't require manual input during movement.

### After the session

The system goes through each exercise and asks for short feedback.

For each exercise:

- did it work? yes/no/partially;
- pain before;
- pain after;
- subjectively: easier / same / harder;
- was it scary or unstable;
- a short comment;
- save the AI video summary, if there was video.

## Deferred feedback

If there's no time in the morning, feedback can be filled in later.

Example flow:

- did the exercises in the morning;
- the system saved a draft session;
- at lunch, a reminder arrives: "Fill in feedback for the morning session?";
- the user quickly walks through the exercises and adds sensations.

## 2-week calibration

After 2 weeks, the system assembles a summary:

- regularity;
- which exercises were performed consistently;
- which were skipped;
- pain trend;
- range-of-motion trend;
- recurring errors;
- which exercises were hard;
- which became easier.

After this, the user updates the plan:

- keep an exercise;
- remove an exercise;
- reduce the load;
- increase the load;
- add a new exercise;
- change the goal for the next 2 weeks.

## The system's role

The system doesn't guide the user during exercise.
The system helps before and after:

- prepare the plan;
- check the reference;
- record the fact of execution;
- collect sensations;
- save the summary;
- show the trend;
- help update the plan for the next cycle.
